Elevators

An Elevator transport represents one elevator bank serving two or more topo-map instances. Its parameters describe the bank, while each station identifies a served landing and its vertical location.

Common station, access, ride-policy, transfer, and output rules are defined in Cross-Map Transportation.

Declaration

transport MainElevator is Elevator {
  let params = {
    maxVelocity = 3.0,
    acceleration = 0.8,
    duty = 1600,
    capacity = 18,
    carAmount = 4
  }

  let displayName = "Main passenger elevators"

  station Lobby at Lobby::main_elevator_landing {
    location = 0.0,
    departureRate = 0.40
  }

  station Office2 at OfficeLevel2::main_elevator_landing {
    location = 4.2,
    departureRate = 0.10
  }
}

Elevator Parameters

An elevator must define a local params record. The recognized fields are:

Field Type Default Meaning
maxVelocity Int or Float 2.5 Maximum car velocity in metres per second.
acceleration Int or Float 0.8 Acceleration in metres per second squared.
carAmount Int 1 Number of cars in the elevator bank.
capacity Int 13 Modeled passenger capacity of each car.
duty Int 1000 Rated carrying load of the elevator.

maxSpeed and cars are not aliases for maxVelocity and carAmount.

Duty and Carrying Load

duty is currently retained in the compiled elevator model for application-side inspection but does not affect route eligibility or route cost. It is intended to participate in a native implicit constraint in a future language version, allowing the engine to compare an elevator's duty with the requested carrying load.

Elevator Station Fields

Every elevator station requires:

Field Type Meaning
location Int or Float Vertical elevation in metres relative to a consistent building datum.
departureRate Float Probability-like departure share used by elevator waiting-time estimation.

An integer departureRate, such as departureRate = 1, is not accepted; write 1.0.

It is strongly recommended that every departureRate remain within the inclusive range 0.0 to 1.0, and that the values across one elevator bank total approximately 1.0. These invariants are not currently enforced by the compiler.

Served Floors

Every declared station is a stop. Every permitted ordered pair of distinct stops is connected directly in the compiled transport graph. Stations need not be written in height order because location establishes their vertical ordering.

An express elevator is modeled by omitting floors at which it does not stop:

station Lobby at Lobby::express_landing {
  location = 0.0,
  departureRate = 0.50
}

station SkyLobby at SkyLobby30::express_landing {
  location = 138.0,
  departureRate = 0.50
}

Elevator Cost Model

Movement time is estimated from the vertical distance between station location values, maxVelocity, and acceleration.

Waiting-time estimation additionally uses carAmount, capacity, station departureRate values, and each served map's permResident. The current model uses an internal fifteen-second dwell-time assumption.

The compiled transport graph currently calculates elevator ride costs using the TopoNavi Engine's up-rush traffic model. Traffic-pattern selection and exact route-cost behavior are implementation-defined routing concerns and are documented in the routing reference.

The station with the lowest location is treated as the entrance station for waiting-time estimation; all other stations are treated as occupant stations.

Station and Ride Access

station F50 at OfficeLevel50::passenger_landing {
  location = 222.0,
  departureRate = 0.04
} requires TradingFloorAccess on Arrive

ride-from any to HotelDomain requires HotelAccess

The station rule controls arrival at this particular stop. The ride policy controls matching directed rides across the management domain. See Station Access and Ride Policies.

Invalid Elevator Declarations

  • The transport must contain a record-valued params binding.
  • Recognized numeric parameters must have the types shown above.
  • Every station must provide a numeric location.
  • Every station must provide a floating-point departureRate.
  • Every qualified station node must resolve to an included topo map and a declared node.
  • An elevator intended for cross-map navigation must serve at least two maps.
