SkyrimTower Mock Building

Status: Draft — transport specification; topo-map sources deferred

Scope

SkyrimTower is a synthetic mixed-use supertall building used to demonstrate stable TopoScript features in a realistic, integrated project. This article currently defines the building program, map-naming assumptions, compilation-time access inputs, station-level controls, and the complete elevator inventory.

Topo-map bodies are intentionally excluded from this draft. Every qualified station reference therefore establishes a node that the corresponding topo map must declare later.

Map-Identifier Contract

The later topo-map sources must use the identifiers referenced by the transport files. Important special cases are:

  • MainLobby represents the connected tower-and-mall area on Level 1.
  • SharedLevel5 represents the connected tower-and-mall area on Level 5.
  • MallLevel7 is separate from the main tower and is served only through mall circulation.
  • RefugeLevel29, ServiceRefugeLevel51, and RefugeLevel71 represent the omitted mechanical or refuge floors.
  • Every station reference of the form MapName::landing_name requires a matching node in MapName.

The future submap declarations must assign these management domains:

  • CarparkDomain: Levels B3 and B2.
  • LogisticsDomain: Level B1.
  • PublicDomain: the main lobby and shared Level 5.
  • MallDomain: Mall Levels 2–4 and 6–7. Shared Level 5 remains in PublicDomain because it is a single connected tower–mall map.
  • OfficeDomain: occupied office floors and the Level 30 sky lobby.
  • RefugeDomain: Levels 29, 51, and 71.
  • HotelDomain: Levels 52–70.
  • ObservatoryDomain: Levels 72–75.

Operational Access Inputs

The elevator systems use destination-sensitive ride policies and station-specific access controls based on emergency state, destination access, carried goods, mall operation hours, and trading-floor authorization. Physical operator control remains part of the fire-service and office-service elevator descriptions, but is not represented as a routing parameter.

root

root SkyrimTower(
  isInEmergency: Bool,
  officeAccess: Bool,
  tradingFloorAccess: Bool,
  hotelAccess: Bool,
  observatoryAccess: Bool,
  logisticsAccess: Bool,
  carryingWeight: Float,
  timeOfDayInSeconds: Int
) {
  constraint InEmergency {
    require isInEmergency
  }

  constraint OfficeAccess {
    require officeAccess
  }

  constraint TradingFloorAccess {
    require tradingFloorAccess
  }

  constraint HotelAccess {
    require hotelAccess
  }

  constraint ObservatoryAccess {
    require observatoryAccess
  }

  constraint LogisticsAccess {
    require logisticsAccess
  }

  constraint CarryingGoods {
    require carryingWeight > 0.0
  }

  constraint InMallOperationHours {
    require timeOfDayInSeconds > 35999
    require timeOfDayInSeconds < 82801
  }
}

CarryingGoods converts the numeric rule carryingWeight > 0.0 into a named constraint usable by ride-from. timeOfDayInSeconds is an integer number of seconds since midnight. Because the current language supports strict comparisons, the bounds above admit every integer from 36000 (10:00:00) through 82800 (23:00:00), inclusive. The hotel service elevators intentionally have no operator or card-reader policy.

Transport Source Conventions

All elevator stations use globally qualified node identifiers and explicit vertical locations. Each departureRate distribution is normalized approximately to one within its elevator system. Transfer floors receive greater rates than ordinary destination floors.

The unannotated car counts and motion parameters are realistic modeling choices for this synthetic example, not universal engineering requirements. They may be refined when representative route outputs are calibrated.

Ride-Policy Model

A rule such as ride-from any to OfficeDomain applies to every origin station on the transport and every destination station whose map belongs to OfficeDomain. The rule does not use a floor identifier as its operand.

The mall elevators require InMallOperationHours for destinations in MallDomain. Their shared Level 5 station is covered by a separate station-specific rule because its map belongs to PublicDomain.

The fire-service elevator does not generally require an active emergency. Carpark and public destinations are unrestricted, mall destinations require normal mall operation hours, and controlled operational domains require their respective access permissions. Only destinations in RefugeDomain require InEmergency.

The office-service elevator distinguishes office, logistics, and refuge destinations. Every ride requires CarryingGoods; office and logistics destinations additionally require access to their respective domains.

The passenger stations on trading Floors 28 and 50 require TradingFloorAccess only on arrival; an unauthorized user may still depart from either floor. The passenger station on Office Level 18 is out-of-order, which prohibits both arrival and departure through that station.
