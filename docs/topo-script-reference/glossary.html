Glossary

This glossary gives short definitions of TopoScript terms and links to the clauses that define their full behavior. It summarizes existing rules and does not introduce new ones.

A B C D E F G H I L M N O P Q R S T U V W

A

Access constraint
A Boolean condition attached with requires that determines whether a path, station use, or transport ride participates in the compiled routing model. See Hard Access Constraints.
Annotation
Data attached to a node or path. Recognized fields may affect filtering or route output; other fields have application-defined meaning. See Node Properties and Path Properties.
any
A ride-from operand that matches every station or management domain at that operand position. See Ride Policies.
Application-defined
Behavior whose meaning is intentionally left to the application consuming TopoNavi Engine output, especially custom annotations. See Stability Boundaries.
Arrive
A station-access qualifier indicating that a requirement applies when arriving at the station. See Station Access.
Atomic path
A direct, directed or bidirectional connection between two nodes in the same topo map that does not cross another intermediate node. It is declared with atomic-path. See Atomicity.
at
The station-declaration connector between a station label and its qualified landing-node identifier. See Stations and Landing Nodes.

B

Base map
A reusable topo-map source named after using when constructing a map instance. See Reusable Submap Instances.
Bool
The primitive Boolean type containing true and false. See Primitive Types.
Building
The compiled collection of selected map graphs, transports, domains, and shared declarations that together describe one routable venue. See Relationship to the Compiled Building.
building-includes
The mandatory project manifest that selects map instances and transports for one compiled building. See Whole-Building Composition.
because
An optional subject-to clause introducing a human-readable reason for uncertain access. See Uncertain Access.

C

Climbing
The route-step category used for stair traversal. See Stair Traversal Time and Transport and Climbing Step Fields.
Compiled building model
The navigation graphs and transport graph produced from a valid TopoScript project and its supplied compilation inputs. See Compiled Routing Model.
Compilation
The process that parses, elaborates, evaluates, and links project sources into a building model. See Language Lifecycle.
Compilation input
An external value supplied for a root parameter while compiling a project. See Compilation Inputs.
Constraint
A named set of Boolean requirements declared with constraint. Multiple require clauses form a conjunction. See Global Constraints.
Cost
A non-negative traversal-time weight used when comparing routes. Atomic-path costs and transport costs are measured in seconds. See Route-Cost Composition.
costSeconds
The route-output field containing one step's traversal time in seconds. See Cost, Duration, and Distance.

D

Disconnected (DC)
An RCC relationship in which two physical node areas share no physical point. See Node Physical Semantics.
def
A declaration of a reusable function or calculated value. Root-level definitions are visible to selected maps and transports. See Global Functions.
Depart
A station-access qualifier indicating that a requirement applies when departing from the station. See Station Access.
Directional arrow
A directional-arrow declaration describing a target node's direction relative to the facing direction established at an anchor node. See Turn Hints.
Domain
Short form for management domain when discussing map grouping and ride policies. It is not a network or internet domain. See Management Domains.

E

Externally connected (EC)
An RCC relationship in which two physical node areas touch at their boundaries but their interiors do not intersect. See Node Physical Semantics.
Edge
A directed connection in a compiled graph. An atomic path produces one edge, or two opposing edges when declared bidirectionally. See Compiled Routing Model.
Elaboration
The compilation phase that resolves names, evaluates declarations and constraints, and converts surface-language declarations into compiled values. See Validation Phases.
Elevator
A multi-station transport whose cost is estimated from waiting and vertical movement time. See Elevators.
Escalator
A two-station fixed-time transport currently modeled as traversable in both directions. See Escalators.
Expression
Source text that evaluates to a value, including literals, names, function applications, operators, records, lists, and conditional expressions. See Expressions and Evaluation.
Experimental
Behavior that may change substantially or be removed, currently including coordinate estimation from spatial relationships. See Stability Boundaries.

F

fix
An expression-language form for explicitly introducing recursion through a fixed-point expression. See Expressions and Evaluation.
Float
The primitive floating-point type. TopoScript does not generally convert between Float and Int implicitly. See Primitive Types.
Floor
The physical building level normally modeled by one topo map. A floor name in prose should not be confused with a map identifier unless the project deliberately uses the same name. See Topo-Map Responsibilities and Boundaries.
fn
A keyword for writing an anonymous function. The backslash form is equivalent. See Expressions and Evaluation.
Function
A value that accepts an argument and produces another value. Function types use ->, and named functions are commonly declared with def. See Function Types.

G

Graph
A compiled collection of nodes and directed edges used by routing. In API output, graph normally contains the identifier of the corresponding topo-map instance. See Waypoints and Identifiers.

H

Hard access
An access condition that removes an unsatisfied path, station permission, or ride from the compiled routing model. Contrast with uncertain access. See Hard Access Constraints.
High-rise routing
A transport-first routing strategy selected with isHighRise=true. It is a strategy name, not a test of the building's physical height. See High-Rise Routing.

I

Identifier
A case-sensitive source name beginning with a letter or underscore and followed by letters, digits, or underscores. See Identifiers and Qualified Names.
if / then / else
The expression-language conditional form. Its condition must be Boolean, and only the selected branch is evaluated. See Expressions and Evaluation.
Implementation-defined
Behavior selected by TopoNavi Engine rather than fixed by TopoScript source semantics, including pathfinding and route-preference handling. See Stability Boundaries.
Int
The primitive signed-integer type. See Primitive Types.
isHighRise
A route-request selector choosing high-rise or fully informed low-rise routing. It does not describe a TopoScript declaration or physical-height threshold. See Building-Routing Modes.
is
The transport-declaration connector between a transport identifier and its kind, as in transport MainLift is Elevator. See Common Transport Declaration Model.

L

Landing node
An existing node referenced by a transport station as the physical endpoint of that transport on a map. See Stations and Landing Nodes.
let
A local value binding. The expression form let name = value in body limits the name to the body; declaration forms may also appear inside supported source bodies. See Expressions and Evaluation.
Linear path
A linear-path hint listing nodes in their physical order along one straight walking line. It groups route output but does not create connectivity. See Straight-Line Hints.
List
An ordered value containing elements of one inferred type. See Composite Types.
Low-rise routing
The fully informed building-wide routing strategy selected with isHighRise=false. The name denotes an algorithmic mode rather than a physical-height test. See Fully Informed Low-Rise Routing.

M

managed-by
A building-includes clause assigning a management domain to one configured map instance. See Management-Domain Attachment.
Management domain
A named grouping of maps, usually based on the party responsible for managing access. Ride policies may use domain names as operands. See Management Domains.
Map
Short form for topo map when referring to a modeled floor and its local topology. It does not mean a metric drawing or coordinate plan. See Topo Maps.
Map instance
A named map included in a building, either directly or constructed from a reusable base with using. Transports and route requests use the instance name. See Reusable Submap Instances.
Metadata
Descriptive or application-facing data attached to compiled entities. Metadata does not affect routing unless a field is explicitly recognized by TopoNavi Engine.

N

Navigation graph
The compiled directed graph for one topo map, formed from its nodes and atomic paths. See Compiled Routing Model.
Node
A named topological entity representing one unambiguous, physically bounded, non-overlapping area of a venue. Source declarations use topo-node. See Nodes.
No-route outcome
A routing result indicating that no complete eligible path connects the requested origin and destination. It is not a partial route. See No-Route Outcomes.

O

out-of-order
A station marker that disables both arrival and departure for an elevator or escalator station. See Station Access.
on
A station-annotation connector used with Arrive or Depart to limit which direction of station use an access condition affects. See Station Access.
override-managed-by
A topo-map declaration clause specifying the map's own management-domain override. See Management-Domain Override.

P

Parameter
A named typed input to a root, map, function, or other parameterized declaration. Root parameters receive application-supplied compilation inputs. See Compilation Inputs.
params
The conventional local record containing recognized map or transport parameters. Its required fields depend on the containing declaration. See Map Parameters and Transport Declarations.
Path
In source-language discussions, normally an atomic path between two nodes. In routing discussions, it may mean an entire selected route. Use atomic path or route when the distinction matters.
Path tag
A canonical string in a path's tags annotation. Tags may participate in request-time traversal filtering. See Banned Tags.

Q

Qualified identifier
A name containing its scope, such as Lobby::main_entrance. For nodes, the left part is the map-instance identifier and the right part is the node's local identifier. See Identifiers and Qualified Names.

R

Record
A value containing named fields, written with braces. Fields are read using projection such as params.capacity. See Composite Types.
rec
A modifier in a let rec expression that introduces an explicitly recursive binding. See Expressions and Evaluation.
Region Connection Calculus (RCC)
The qualitative spatial framework used here to state that distinct node areas must be disconnected (DC) or externally connected (EC), never overlapping. See Node Physical Semantics.
require
A clause inside a named constraint. Its expression must evaluate to Bool. See Global Constraints.
Required action
An application-facing instruction attached to a path, such as tapping an access card or opening a door. It is reported but does not change route eligibility or cost. See Required Actions.
requires
An annotation attaching one or more named hard access constraints to a path, station use, or ride policy. Contrast with the singular require clause inside a constraint declaration.
ride-from
A directed policy controlling rides between station labels, management domains, or any. It is not a whitelist: unmatched rides remain permitted. See Ride Policies.
Risk preference
A request-time control deciding whether routes with uncertain access may be selected. See Risk Preferences.
root
The optional project-global source declaration providing shared parameters, constraints, and functions. It does not create a navigable map. See The Root Source.
Route
A traversable ordered result consisting of walking edges and transport movements between an origin node and a destination node. See Route Entity.
Route-planning preference
A request-time choice controlling how eligible route candidates are ranked, such as MinimizeTime, MinimizeTransfers, or MinimizePhysicalDemands. See Primary Route-Planning Preferences.
Route step
One ordered consumer-facing segment of a route result, such as Walk, WalkStraight, Transport, or Climbing. See Step Order and Types.

S

Stairs
A cross-map transport whose cost represents climbing time. See Stairs.
Station
A labeled transport stop connecting one transport to one existing landing node in a map. See Stations and Landing Nodes.
Station label
A name local to one transport declaration. Ride policies may use it as an operand; it is distinct from the map and landing-node identifiers. See Stations and Landing Nodes.
String
The primitive character-sequence type represented by a double-quoted literal. See Primitive Types.
subject-to
An annotation recording uncertain access without removing the affected path or station use from the compiled model. An optional because clause supplies a human-readable reason. See Uncertain Access.
submap
A building-includes entry selecting or instantiating a topo map. Despite its name, it does not create a parent-child map hierarchy. See No Parent-Map Hierarchy.

T

Tag
A canonical string classifying a map entity for application use or recognized traversal filtering. See the TopoScript Tagging Guide.
Topological
Describing connectivity, adjacency, and navigation-relevant relationships without requiring metric coordinates or a geometrically accurate floor plan.
to
The ride-from connector separating its directed source and destination operands. See Ride Policies.
Topo map
A graph-like declaration representing the navigable topology of one particular floor. It contains nodes, atomic paths, and optional navigation hints. See Topo Maps.
topo-node
The source declaration for a node in a topo map. See Node Syntax.
TopoScript
The domain-specific language used to describe an indoor venue's routable topology, cross-map transportation, access conditions, and navigation-relevant metadata. See Category of System.
Transport
A connection between multiple topo maps. Supported transport kinds are Elevator, Escalator, and Stairs. See Cross-Map Transportation.
Transport graph
The compiled graph connecting transport stations across otherwise independent map graphs. See Compiled Routing Model.
true and false
The two literals of type Bool. See Primitive Types.
type
A parser-supported named type declaration. Its intended long-term role at building-global scope remains under design review and is not part of the stable global surface. See Documented Global Declarations.

U

Uncertain access
A condition indicating that a path or station use may not be available, while allowing risk-aware routing to decide whether it may participate. See Uncertain Access.
using
A submap clause constructing a named map instance from a reusable base topo-map source. See Reusable Submap Instances.

V

vehicle
The current building-includes keyword that selects a transport source. In explanatory prose, the canonical term is transport. See Whole-Building Syntax.
Visiting mode
An internal routing concept historically used for mode-specific path costs. It is not part of the stable request-facing TopoScript reference at present.

W

Waypoint
A structured node record included in a route step. Its graph and nodeId fields identify the corresponding TopoScript node. See Waypoints, Identifiers, and Descriptions.
Walk
A route-step type grouping one or more consecutive walking edges on the same map. See Step Order and Types.
WalkStraight
A walking route step recognized as lying along one declared linear-path. See Spatial and Turn Hints.

Important Terminology Distinctions

  • Node and point: a node represents a bounded physical area, not an infinitesimal coordinate point.
  • Atomic path and route: an atomic path is one direct local connection; a route is the complete ordered journey.
  • Topo map and floor plan: a topo map models navigation topology, not metric geometry or architectural drawing data.
  • Map and graph: a topo map is the source-language declaration; a navigation graph is its compiled routing representation.
  • Map and submap: submap is the manifest keyword for a configured map instance; it does not imply containment beneath a parent map.
  • Transport and vehicle: transport is the canonical concept; vehicle is the current manifest keyword used to select a transport source.
  • require and requires: require appears inside a constraint declaration; requires attaches a named constraint to another declaration.
  • Hard and uncertain access: failed hard access removes an option; uncertain access remains available only according to risk preference and is disclosed in the result.
  • Station label and landing node: a station label names a stop within one transport; a landing node names the physical area in its topo map.
  • Floor and map identifier: floor labels are real-world descriptions; map identifiers are exact, case-sensitive source names.
